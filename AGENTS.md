# Repository workflow

- Always commit and push repository changes unless the user says otherwise.
- Comments are allowed when documenting research that was done. Cite the source,
  explain how the code reflects the findings, and distinguish observed behavior
  from artistic or implementation choices.
- Prefer extending existing test scenarios over adding a new test for each change.
  Consolidate duplicate coverage and share setup so the suite stays organized and fast.
- When adding a page, include it in `src/pages/sitemap.xml.ts`, provide structured
  data through `BaseLayout`, and run `tests/integrity.spec.ts`; the integrity check
  requires internal link destinations to be in the sitemap with page metadata.

## Generated content ownership

- `src/data/pigeons.json`, `src/data/publication.schema.json`, and
  `src/assets/` are publisher-owned output. Do not
  hand-edit photo records or titles there. Change publication
  output in sibling `pigeon-queue/pigeon/website.py`; edit unpublished photos
  through `pigeon-queue/bin/serve`.
- Descriptive photo titles are generated by pigeon-queue; use its documented
  `--refresh-titles` command to regenerate existing titles.
- The handwritten JSON adapter belongs in `src/data/pigeons.ts`.
  Website types and presentation belong in `src/data/pigeon-photo.ts` and
  `src/data/pigeon-posts.ts`, plus the Astro components/pages.
- `.pigeon-queue/` receipts and number reservations are publisher state, not
  editable content. Preserve them and existing permanent post numbers.

## Publishing intent

- Keep the repository split: the private queue automates publishing and hides the
  full unpublished queue/upcoming schedule. Minor exposure around one started
  post is acceptable; never put the full schedule or drafts in this public repo.
- Website and Bluesky are independent targets. Neither target's failure may block
  the other or later daily posts. A reserved page link may be temporarily unavailable
  when Bluesky publishes first. Do not reintroduce a website-live prerequisite.
- Independent, idempotent retries and private durable reservations belong to
  pigeon-queue. This repository renders and deploys published content only.
- Consume the versioned JSON contract and validate it at build time. Never make
  TypeScript formatting the cross-repository publishing API. Preserve existing
  permanent numbers, URLs, dates, captions, alt text, and image bytes in migrations.
